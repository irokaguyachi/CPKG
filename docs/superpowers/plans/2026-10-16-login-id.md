# 아이디 로그인 전환 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 20자리 로그인 코드 대신 유저가 정한 아이디만으로 로그인하게 하고, 마감 뒤 아이디 없는 계정을 프로덕션 예약 작업이 자동으로 지운다.

**Architecture:** 서버 내부 열쇠는 기존 개인 코드 그대로 두고 D1 `login_ids`(아이디 → 코드)를 얹는다. 브라우저는 아이디로 코드를 받아 지금과 같은 경로로 동작한다.
마감 뒤 정리는 `maintenance_jobs` 에 진행 상태를 둔 이어하기 방식의 매분 작업이고, `ACCOUNT_SWEEP_ENABLED = "1"` 인 프로덕션에서만 돈다.

**Tech Stack:** Cloudflare Workers(ES modules), D1, R2, 브라우저 ES5 스크립트, Node 테스트 러너(`npm test`).

**Spec:** `docs/superpowers/specs/2026-10-16-login-id-design.md`

## Global Constraints

- 아이디 규칙: 입력을 `trim()` 후 소문자로 바꾼 값이 `^[a-z0-9_]{4,20}$`. 저장·비교는 소문자.
- `LOGIN_CODE_DEADLINE = Date.UTC(2026, 9, 31, 15, 0, 0)` (2026-11-01 00:00 KST). 서버(`worker/loginIdConfig.js`)와 브라우저(`UserData.LOGIN_CODE_DEADLINE`)가 같은 값.
- `LOGIN_ID_COOLDOWN_MS = 86400000`. 처음 만들 때는 `changed_at = 0`(바로 변경 가능), 변경할 때만 적용. 같은 아이디 재설정은 변경 아님.
- 안내 문구 원문: "이제 로그인 코드는 폐지됩니다! 아이디를 변경하세요! 10월 31일 오후 11:59에 변경하지 않은 로그인 코드는 계정이 삭제됩니다!"
- 오류 본문: 중복 `{ error: 'login id taken' }` 409, 형식 `{ error: 'invalid login id' }` 400, 없음 `{ error: 'login id not found' }` 404, 쿨타임 `{ error: 'login id cooldown', retryAt }` 429, 마감 뒤 코드만 가입 `{ error: 'account deleted' }` 410.
- 정리 작업은 `env.ACCOUNT_SWEEP_ENABLED === '1'` 일 때만. 이 값은 `src/wrangler.toml` 최상위 `[vars]` 에만 넣고 `[env.dev.vars]` 에는 절대 넣지 않는다(dev 와 프로덕션이 같은 D1·R2 를 쓴다).
- 계정 삭제 작업(미커밋, 같은 작업 트리)의 `worker/accountDelete.js`·`worker/accountKeys.js` 를 재사용한다. 해시 공식은 바꾸지 않는다.
- 브라우저 코드 ES5, 새 문구 `I18n.t` + English/Japanese, 이후 `python src/scripts/10_update_data_version.py`.
- 커밋하지 않는다(사용자가 dev 반영 직전에 확인). 다른 미커밋 변경(미러볼·푸터·계정 삭제)은 되돌리지 않는다. 배포·원격 wrangler 명령 금지.

## Review Focus

- 옛 브라우저가 마감 뒤 동기화 404 → 코드만 자동 재가입 — 410 이어야 하고 계정이 생기면 안 된다. (Task 2)
- 아이디 변경 중 다른 사람이 같은 아이디를 동시에 잡는 경우 — UNIQUE 충돌을 409 로, 예전 아이디가 사라지거나 둘 다 남지 않아야 한다. (Task 1)
- 정리 작업이 dev 에서 도는 경우 — 스위치가 없으면 마감 뒤에도 아무것도 지우지 않는다. (Task 3)
- 정리 도중 새 아이디가 생기는 경우 — 매 틱 `login_ids` 를 다시 읽어 방금 전환한 계정을 지우지 않는다. (Task 3)
- 이미 로그인돼 있던 코드 사용자 — 페이지를 열면 `/login-id/me` 로 판별돼 안내·변경 창이 뜬다. (Task 4·5)

  - `login returns the code for an id` — 계정 생성 후 `insertLoginId` 로 `'kim_01'` 연결 → `POST /user/login { loginId: 'KIM_01' }` 200 `{ personalCode, loginId: 'kim_01' }`; 없는 아이디 404 `login id not found`; `'ab'` 400 `invalid login id`.

  - `set for a missing account is 404`, `set/me for a deleted account is 410 account deleted`.
  - `me reports loginId and changeableAt` — 없으면 `{ loginId: null, changeableAt: 0 }`, 변경 뒤 `changeableAt === changed_at + 86400000`.

  - `does not delete an account converted during the sweep` — 'users' 단계 일부 진행 뒤 D 에 아이디를 넣고 이어서 호출 → D 의 남은 데이터가 지워지지 않음.
