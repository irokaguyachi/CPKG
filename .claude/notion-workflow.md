# 노션 정리 작업 기록 (.claude/notion-workflow.md)

카붕이 문학(로컬 `문학 정리/`)을 노션에 옮겨 정리한 작업 내역과 재현 방법을 기록합니다. 이후 세션에서 같은 방식으로 이어서 작업하거나 새로 추가할 때 참고합니다.

---

## 1. 노션 구조

```
본진 (페이지)
└─ 명예관 (페이지, icon 🏆)
   └─ 명예관 문학 (인라인 DB)
└─ 시리즈 (페이지)
   └─ 시리즈 문학 (인라인 DB, icon 📚)
```

| 대상 | Page/DB ID |
|---|---|
| 명예관 페이지 | `3b0939dd-9463-80eb-9721-edbd9b99a035` |
| 명예관 문학 DB | `3b2939dd-9463-8064-8ba4-e6efee522064` (data source `3b2939dd-9463-8074-ab93-000b39cfaa5a`) |
| 본진 페이지 | `3b5939dd-9463-80f1-9cb8-d2108151e852` |
| 시리즈 페이지 | `3b5939dd-9463-809d-9167-f4393d039dca` |
| 시리즈 문학 DB | `3b5939dd-9463-80dc-bcba-f7b1a1cb6300` (data source `203939dd-9463-8219-9b5c-872ed487bf14`) |
| 커스텀 이모지 "디시" | `3b5939dd-9463-803b-943a-007a7d080589` |

⚠️ 두 DB는 서로 **다른 Notion 인테그레이션에 공유**되어 있었음(명예관은 개인 API 키 + 공식 MCP 둘 다, 시리즈는 처음엔 공식 MCP만 → 이후 사용자가 개인 API 키 쪽에도 "연결 추가"로 공유해줌). 접근 안 되면(404 `object_not_found`) 십중팔구 공유 문제이니, 어느 쪽 인테그레이션으로 접근 중인지부터 확인할 것.

## 2. DB 스키마

두 DB 모두 동일한 형태: **이름**(title) / **태그**(multi_select) / **생성일**(created_time, 자동).
행/열을 추가로 만들지 않고 이 스키마 그대로 사용했음 (사용자가 이미 세팅해둔 스키마를 존중).

### 태그 옵션 (이모지 프리픽스 있는 것 = 사용자가 미리 만들어둠)

| 원래 태그(.agent/rules/tag.md) | 노션 옵션명 |
|---|---|
| 일상 | `☕ 일상` |
| 슬픔 | `💧 슬픔` |
| 감동 | `😭 감동` |
| 로맨스 | `💕 로맨스` |
| 피폐 | `🥀 피폐` |
| 코미디 | `🤣 코미디` |
| 후방주의 | `🔞 후방주의` |
| 글카스 | `💩 글카스` |
| 명예관 | `🏆 명예관` |
| 장문 | `장문` (이모지 없음, 명예관 DB 전용) |
| 소설 | `소설` (이모지 없음, 명예관 DB 전용) |
| 단편 / 짧문 | `짧문학` (이모지 없음, 명예관 DB 전용) |
| 장편 (신설, 10화 이상 시리즈) | `장편` (이모지 없음, green, 시리즈 DB 전용) |
| 단편 (신설, 3화 이하 시리즈) | `단편` (이모지 없음, orange, 시리즈 DB 전용) |

미스테리/SF/AI/로카/If스토리/이모티콘 옵션은 없음 — 명예관·시리즈 데이터에 실제로 등장하지 않아서 안 만듦.

⚠️ **시리즈 문학 DB는 개별 게시글 분량 태그(`짧문학`/`소설`/`장문`)를 쓰지 않음(2026-08-10부터).** 회차마다 글자 수가 달라 시리즈 전체를 대표할 수 없기 때문. 대신 회차 수 기준 `장편`(10화 이상)/`단편`(3화 이하)만 사용. 자세한 기준은 `.agent/rules/tag.md` 2-0~2-0-2절 참고. (명예관 문학 DB는 개별 게시글 기준이라 `짧문학`/`소설`/`장문` 그대로 사용.)

⚠️ **공식 MCP(`mcp__claude_ai_Notion__notion-update-page`)는 존재하지 않는 multi_select 옵션 이름을 주면 자동 생성되지 않고 400 에러가 남** (raw API와 다름). 새 태그가 필요하면 먼저 `notion-update-data-source`의 `ALTER COLUMN "태그" SET MULTI_SELECT(...)`로 **기존 옵션 전체를 그대로 나열 + 새 옵션 추가**한 뒤 페이지에 반영할 것. 기존 옵션을 하나라도 빠뜨리면 유실되므로 실행 전 반드시 `notion-fetch`로 현재 옵션 전체를 확인.

### 장편/단편 태그 적용 이력 (2026-08-10)

`.agent/rules/tag.md` 2-0절 기준(회차 10화 이상)으로 시리즈 문학 DB의 아래 12개 페이지에 `장편` 태그 추가 완료(명예관 출처 페이지는 `🏆 명예관` 바로 뒤에 배치): 우리의 해피엔딩(10화), [나, 사카요리 이로하는], 그들의 해피엔딩을 위해, 전생 했더니 초 카구야 공주 세계관에 와버렸습니다, 히키코모리 이로하, 여우가 머문 자리, 나에게 너무 적극적인 전학생!, 아침햇살은 언제나 빛나는 나뭇잎을 비추고있었다., 또 다른 카구야와 조우, 주의) 무언가 잘못된 해피엔딩, 카구야 오배송, 수취인 아즈마 미오, [칭찬일기](67화, 신규 생성).

같은 날 2-0-1/2-0-2절 기준으로 **회차 3화 이하 34개 페이지**에 `단편` 태그를 추가하고, 전체 DB에서 `짧문학`/`장문` 태그를 제거함(스키마 옵션 자체는 명예관 DB와 공유라 삭제하지 않고 유지, 시리즈 DB 페이지에서만 사용 중단).

**칭찬일기(67화)는 이 세션에서 신규 생성 완료** — `mcp__claude_ai_Notion__notion-create-pages`로 생성 후 `insert_content`로 67화 전체 append. 태그는 `[장편, 💧 슬픔]` (짧문 태그는 시리즈 DB 규칙상 제외). 대표 이미지(271843_1.jpg)는 `notion-create-file-upload`가 지속적으로 500 에러를 반환해 업로드 실패, 이번엔 생략함 — 필요시 재시도.

**MCP로 페이지 컨텐츠 작성 시 주의**: `notion-update-page`의 `content`/`new_str` 파라미터에 실제 개행 대신 리터럴 `\n` 텍스트를 넣으면 그대로 문자 `\n`으로 들어가 마크다운이 깨짐(헤더와 링크가 한 줄로 뭉개짐). 반드시 진짜 줄바꿈 문자를 사용할 것. `create-pages`의 JSON `content` 필드는 정상적으로 `\n`을 개행으로 파싱함.

## 3. 명예관 문학 페이지 포맷

- **대상**: `문학 정리/명예관/*.md` 중 `명예관.md`·`Ignore명예관.md` 제외한 개별 파일(29개) → 이 중 **이미 시리즈에 통합된 6건은 제외**하고 최종 23건만 등록.
- **아이콘**: 🏆 (고정)
- **제목**: `{장르 이모지들} | [게시글번호] 원본 제목` — 이모지는 태그의 장르 태그(명예관/길이 태그 제외)를 태그 순서대로 이어붙임. 장르 태그가 없으면 이모지 없이 `[ID] 제목`만.
- **태그 속성**: 원문의 태그 전체(길이 태그 포함) 중 `명예관`만 제외하고 반영.
- **본문 블록 순서**:
  1. 이미지 (원문 첨부 사진 중 첫 장. 없으면 이 블록 생략)
  2. `divider`
  3. `heading_1`: 고정 텍스트 **"본문"** (실제 문학 텍스트를 나중에 채워 넣을 자리, 현재는 비어있음)
  4. `paragraph`: 커스텀 이모지 `:디시:` + 스페이스 + `[게시글번호] 제목` (전체가 원본 디시 게시글 URL로 하이퍼링크)

## 4. 시리즈 문학 페이지 포맷

- **대상**: `문학 정리/시리즈/*.md` 전체 78개, 1파일 = 1 노션 페이지(행).
- **아이콘**: 없음 (DB 자체 아이콘 📚로 충분하다고 판단, 개별 페이지엔 안 넣음)
- **제목**: 시리즈 파일의 `**시리즈명**` 값 그대로.
- **태그 속성**: 시리즈 파일의 `**시리즈 태그**` 값을 위 표대로 매핑. **단, 명예관에서 발굴/통합된 시리즈 5개**(아래 5절)는 `🏆 명예관`을 태그 맨 앞에 수동 추가함.
- **본문 블록 순서**:
  1. 대표 이미지 1장 — 시리즈 내 회차들을 순서대로 훑어서 **처음 발견되는, 5MB 이하인** 사진 1장만 사용. 5MB 넘으면 다음 후보 사진으로 자동 대체, 아예 사진이 없으면(78개 중 35개) 이 블록 생략.
  2. `divider`
  3. 회차마다 반복: `heading_2` `"{시리즈명} - N화"` (N은 회차 순번, 1부터) → 바로 아래 `paragraph`: `:디시:` + 스페이스 + `[게시글번호] 회차제목` (원본 URL 하이퍼링크)
- 노션 페이지 children 생성은 1회 API 호출당 최대 100블록 제한이 있어, 회차가 많은 시리즈(예: 나에게 너무 적극적인 전학생! 32화)는 첫 100개는 페이지 생성 시, 나머지는 이어서 `PATCH .../blocks/{page_id}/children`로 추가 append.

### 명예관 소재가 섞인 시리즈 (🏆 명예관 태그 추가 대상)

| 시리즈명 | 비고 |
|---|---|
| `[나, 사카요리 이로하는]` | 2개 회차가 명예관 출처 |
| `이로하가 없는 해피엔딩` | 2개 회차 전부 명예관 출처 |
| `여우가 머문 자리` | 1화가 명예관 출처 |
| `야치요와 이로하가 기억을 지운 이야기` | 1화(원래 시리즈 파일에 누락돼있던 회차)가 명예관 출처 |
| `초 야치요 마이너갤러리` | 명예관 2편 + 크롤링 파일 2편을 합쳐 **이번에 새로 만든 시리즈** |

## 5. API 접근 방식 — 언제 무엇을 쓸지

두 가지 경로가 있고 성격이 다름:

1. **개인 API 키(raw REST, curl/`requests`)** — 세밀한 제어(이미지 업로드, 커스텀 이모지 ID 직접 지정, 블록 순서 세팅, 태그 배열 순서 조정 등)가 전부 되는 유일한 방법. **이 저장소 작업은 전부 이 경로로 함.** 단, 페이지/DB가 이 인테그레이션에 "연결 추가"로 공유되어 있어야 접근 가능(404면 공유 문제부터 의심).
2. **공식 Claude Notion MCP** (`mcp__claude_ai_Notion__*`) — 마크다운 기반이라 간편하지만 한계가 뚜렷함:
   - `:디시:` 같은 커스텀 이모지 마크다운 문법이 이름으로 해석이 안 되고 그냥 텍스트로 남음 (raw API로 ID 직접 지정해야 확실함).
   - `bookmark`/`link_preview` 블록 생성 자체가 지원 안 됨 (마크다운 스펙에 아예 없음) → 링크는 하이퍼링크 텍스트로 대체.
   - 대신 워크스페이스 탐색(`notion-fetch`, `notion-search`)이나 페이지 구조 파악에는 유용함.

### 얻은 교훈 / 주의사항

- **multi_select 옵션 이름은 API로 안전하게 리네임 불가.** 기존 옵션 id를 유지한 채 `name`만 바꿔 PATCH해도 조용히 무시되거나(최악의 경우) 옵션 목록 전체가 날아가는 사고가 실제로 있었음(13개 중 11개 증발 → 원본 스냅샷으로 복구). **이름을 바꾸고 싶으면 새 옵션을 만들어서 각 페이지에 재할당**하는 (추가형) 방식만 쓸 것.
- **이미지 업로드 5MB 제한**(무료 플랜). 초과 시: (a) 같은 글의 다른 사진으로 대체하거나 (b) ffmpeg로 압축(예: gif는 `scale=640:-1,palettegen/paletteuse` 팔레트 재인코딩으로 대폭 축소 가능).
- **Bookmark 리치 프리뷰(썸네일·제목)는 API/자동화로 절대 못 만듦** — 브라우저로 페이지를 열람해도 안 됨, MCP로 만들어도 안 됨. 사람이 노션 에디터에 로그인해서 직접 붙여넣기 할 때만 생성됨. 그래서 이 저장소는 리치 카드 대신 "커스텀 이모지 + 하이퍼링크 텍스트" 방식을 표준으로 채택함.
- **API 키를 채팅에 평문으로 주고받지 말 것.** 이번 세션에서 사용자가 직접 채팅에 붙여넣은 적이 있어 작업 후 재발급(rotate)을 권장했음. 이 문서나 코드에 실제 키 값을 하드코딩하지 않음.

## 6. 재현/확장 시 체크리스트

새 명예관 글이나 새 시리즈를 추가로 노션에 올릴 때:

1. 로컬 소스(`문학 정리/명예관/*.md` 또는 `문학 정리/시리즈/*.md`)에서 제목/링크/태그/사진 경로를 파싱.
2. 태그를 위 매핑표로 변환 (없는 옵션이면 그냥 새로 생성됨).
3. 대표 이미지 후보를 순서대로 시도하며 5MB 이하인 것으로 업로드 (`POST /v1/file_uploads` → `POST .../send`).
4. 본문 블록을 정해진 순서(3·4절)대로 구성해 페이지 생성 (`POST /v1/pages`, parent는 `database_id`).
5. 회차/블록이 100개를 넘으면 나머지는 `PATCH /v1/blocks/{page_id}/children`로 이어붙임.
6. 명예관 출처가 섞인 시리즈라면 `🏆 명예관` 태그를 배열 맨 앞에 추가.
