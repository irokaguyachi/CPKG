# 시리즈 문학 관리 규칙 (rules/SeriesRule.md)

연재/시리즈 형태의 문학 게시글을 식별하고 정리하는 절차를 규정합니다.

---

## 1. 시리즈 판별 기준

1. **디시인사이드 자체 시리즈 기능 (`series_no`) [1순위]**: 본문의 디시 공식 시리즈 ID/시리즈명을 수집하여 100% 정확히 동일 시리즈로 자동 묶음.
2. **제목 패턴 기반 보완 [2순위]**: 디시 시리즈 미설정 글은 제목 패턴(예: `씹덕망상글`, `씹덕망상글2`~`씹덕망상글5`, `-1-`, `-2-`, `1/n` 등)을 검증하여 보완 판단.
3. **등장인물/서사 연속성 보완**: 제목 패턴이 애매한 경우, 등장인물과 이야기 흐름의 연속성을 대조하여 동일 시리즈 여부를 최종 판단.
4. **작성자 판단**: `작성자` 필드가 명시된 경우 동일 필명/코드로 일치 여부를 확인하고, 필드가 누락된 경우(예: 기본 작성자) 제목 번호 연속성과 등장인물 연속성을 근거로 동일 작성자 여부를 판단.

---

## 2. 정리 절차 (3단계 동시 작업 — 하나라도 누락 금지)

시리즈로 판별된 게시글은 아래 3곳에 **모두** 반영해야 합니다. 원본 `크롤링 파일/N.md`의 항목은 **삭제하지 않고 그대로 유지**합니다.

### ① 원본 `크롤링 파일/N.md` 표시
- 해당 게시글 헤더의 **ID 바로 옆에 `[시리즈]` 표기**를 추가합니다.
- 예: `### [23087][시리즈] 씹덕망상글) 8000번째 이벤트`

### ② `문학 정리/시리즈/<시리즈명>.md` 생성/갱신
- 시리즈별 독립 파일을 생성하며, 파일명은 시리즈명 그대로 사용합니다. (예: `시리즈/씹덕시리즈.md`)
- 상단에 시리즈 정보(시리즈명, 총 회차, 작성자, 판별 근거)를 기록합니다.
- 회차는 `시리즈 1: [게시글]`, `시리즈 2: [게시글]` ... 순서(연재 순, 오래된 회차부터)로 정리합니다.
- 각 회차 항목에는 원본과 동일하게 게시물 이름(ID 포함), 게시물 링크, 태그, 글자 수, 첨부 사진 경로를 기록합니다.
- 새로운 회차가 추가로 발견되면 해당 시리즈 파일 하단에 이어서 통합 관리합니다.

### ③ `.agent/SeriesID.md` 등록
- `ignoreID.md`와 유사하게 관리하되, 형식은 아래처럼 **시리즈명 한 줄 + ID 목록**으로 작성합니다.

```
씹덕망상글
23087
23145
23214
23370
23734
```

- 여러 시리즈가 등록될 경우 시리즈명 단위로 빈 줄로 구분하여 이어서 추가합니다.
- AI 에이전트는 크롤링/정리 전 이 목록을 참고하여 해당 ID가 이미 어느 시리즈에 속해 있는지 먼저 확인합니다.

### ④ `.agent/SeriesNotFound.md` 갱신
- 회차 번호상 존재해야 하지만 크롤링 데이터 내에서 원문을 찾지 못한 회차가 있으면, 표에 `시리즈명 | 누락 회차 | 비고` 형식으로 한 줄 추가합니다.
- AI 에이전트는 신규 크롤링/정리 작업 중 이 표와 일치하는 게시글을 발견하면 해당 시리즈 파일에 회차로 추가하고, 표에서 해당 항목을 제거합니다.

---

## 3. 주의사항

- 시리즈로 편입되었다고 해서 원본 `크롤링 파일/N.md`의 항목을 삭제하거나 이동하지 않습니다. (배치 파일의 게시글 ID 범위 무결성 유지 목적)
- 사진 파일은 기존 경로(`사진/N/게시물번호_순번.확장자`)를 그대로 참조하며, 별도 이동/재배치를 하지 않습니다.
- 시리즈 데이터는 `src/scripts/2_parse_series.py` 및 `5_build_series_page_data.py`를 통해 사이트 데이터로 변환되어 관리됩니다.
