# 크롤링 규칙 (rules/crawling.md)

   - 게시글 번호(ID)의 실제 범위에 맞춰 해당 파일에 수집 및 정리를 진행합니다. (규칙: `크롤링/N.md` = ID `(N-1)*10,000+1` ~ `N*10,000`)
     - **`크롤링/1.md`**: 게시글 번호 **1 ~ 10,000번**
     - **`크롤링/2.md`**: 게시글 번호 **10,001 ~ 20,000번**
     - **`크롤링/3.md`**: 게시글 번호 **20,001 ~ 30,000번**
     - *(4~27.md는 동일 규칙으로 10,000번 단위 순차 증가)*
     - **`크롤링/28.md`**: 게시글 번호 **270,001 ~ 280,000번**
     - **`크롤링/29.md`**: 게시글 번호 **280,001 ~ 290,000번** (기존 수집 마감 구간: ID ~281,889번 완료)
     - **`크롤링/N.md`(30 이상)는 생성하지 않음**: 아래 "29.md 수집 마감" 항목 참조
   - 📅 **29.md 수집 마감 및 향후 날짜별 수집 규칙**:
     - 기존 전체 기본 크롤링 배치는 최신 게시글 ID **`281,889`번(`29.md`)**까지만 마감 작성합니다.
     - `29.md` 이후(ID > 281,889) 향후 등록되는 신규 문학 글은 숫자 배치 파일(`30.md` 등)을 더 이상 생성하지 않고, **날짜별 수집(일별/주별 갱신)** 체계로 전환하여 관리합니다.


2. **사진/이미지 다운로드 및 저장 규칙**:
   - 게시글 본문에 첨부된 사진/이미지는 각 차수(`1.md`, `2.md`...)에 맞게 **`사진/1/`**, **`사진/2/`** 등 해당 번호의 하위 폴더를 생성하여 저장합니다.
   - ⚠️ **로딩 대기, 스크롤 다운 및 정상 다운로드 지침**:
     - 디시인사이드 특성상 레이지 로딩 및 임시 주소(`.php` 등) 로딩으로 인한 이미지 누락을 방지하기 위해 **페이지 본문 스크롤 다운(Scroll Down)**을 실행하고 **5~10초 대기**하여 모든 고화질 원본 이미지가 로딩된 후 다운로드를 수행합니다.
     - 다운로드 완료 시 임시 확장이 아닌 실제 이미지 포맷(`jpg`, `png`, `gif` 등)으로 변환 및 검증하여 저장합니다.
   - **사진 파일 경로 및 명칭 체계**:
     - **단편 문학**: `사진/차수/게시물번호_순번.확장자` (예: `사진/1/1024_1.jpg`)
     - **시리즈 문학**: `사진/시리즈/시리즈명/게시물번호_순번.확장자` (예: `사진/시리즈/나에게 너무 적극적인 전학생!/82751_1.jpg`)

3. 🚨 **사이트 부하 방지 및 요청 간격(Delay) 필수 지침 (중요)**:
   - **게시글 요청 간 텀(Delay) 적용**:
     - 연속 요청으로 인한 서버 트래픽 부담, 사이트 불안정, 차단(IP Block / 429 Too Many Requests) 방지를 위해 게시글 수집 시 **각 요청 사이 최소 1~3초 간격(Delay)**의 대기 시간을 부여합니다.
   - **동시성(Concurrency) 제어**:
     - 대량 수집 및 태그 판독 작업 시 병렬 동시 요청 수를 **최대 2~3개 이하**로 제한합니다.
     - 수집 진행 중 20~30건 단위마다 **3~5초의 추가 휴식 텀**을 둡니다.
   - **오류 및 차단 대처 (Backoff)**:
     - 429, 502/503/504 에러 또는 연결 타임아웃 발생 시 즉시 재요청하지 않고 **5~10초 간격으로 지연 시간을 늘려 재시도(Exponential Backoff)**합니다.

4. **수집 데이터 및 결과 정리 위치**:
   - 게시글 번호, 제목, URL, 본문 텍스트, 다운로드된 사진 파일 경로 목록을 수집합니다.
   - 크롤링 및 정리 결과 마크다운 파일은 **`크롤링/` 폴더 하위**에 10,000개 단위(`크롤링/1.md`, `크롤링/2.md` ...)로 생성 및 관리합니다.

5. **크롤링 현황 기록 (`CurrentStats.md`)**:
   - 매 크롤링 작업이 완료될 때마다 **`CurrentStats.md`** 파일에 크롤링 진행 상황을 업데이트하여 기록합니다.
   - **필수 기록 항목**:
     - **마지막 크롤링한 페이지 번호 및 게시글 ID**
     - **크롤링 실행 및 완료 날짜/시간** (예: `2026-08-05 22:40:15`)
     - **최종 작업 완료 파일 및 수집 건수** (예: `크롤링/2.md`)
     - **총 수집 문학 건수 (단편/시리즈 총합) 및 총 수집 시리즈 건수**
     - **총 수집 글자 수 (및 UTF-8 텍스트 용량)**
     - **총 수집 사진 수 및 총 사진 용량 (MB/GB/Bytes)**

6. 🚫 **robots.txt에 의한 Claude 자동 수집 전면 금지 (`.agent/dc.robot.txt` 참조)**:
   - `m.dcinside.com` robots.txt는 `ClaudeBot`, `anthropic-ai`, `Claude-Web`을 명시적으로 **전체 차단(`Disallow: /`)**하고 있습니다. 다른 봇(`User-agent: *`)은 대부분 허용되지만 Anthropic 계열만 콕 집어 차단된 상태입니다.
   - **왜 중요한가**: AI 에이전트(Claude)가 이 지침을 무시하고 User-Agent를 브라우저인 것처럼 위장해 우회 수집하는 것은 사이트 운영자의 명시적 의사에 반하는 행위이므로 절대 금지합니다.
   - **실무 지침**: Claude 기반 에이전트는 `chokaguyahime` 갤러리 게시글을 자동/직접 크롤링(WebFetch, 브라우저 자동화 등)해서는 안 됩니다. 대신 ①사용자가 직접 브라우저로 열람 후 본문을 붙여넣어 전달하거나, ②사용자가 별도 수집한 원본 데이터 파일을 읽는 방식으로만 콘텐츠를 확보합니다.
   - 차단 경로(`/search/`, `/api/`, 특정 차단 갤러리/게시글, `/gallog/`) 역시 어떤 방식으로도 접근하지 않습니다.

7. 🚨 **본문 파싱 고립성 수칙 (`<div class="write_div">` 추출)**:
   - 본문 텍스트 수집 및 글자 수 계산 시, 디시인사이드 페이지 HTML 전체에서 **오직 `<div class="write_div">` 내부 텍스트만 추출**합니다.
   - 댓글, 답글, 스크립트 코드(`<script>`), 사이드바, 공지사항, 목록 테이블, 광고 노출 텍스트는 100% 필터링하여 제외해야 합니다.

8. ⏳ **동적 DOM 완전 로딩 대기 수칙 (3~5초 대기 필수)**:
   - 디시인사이드 게시글 텍스트 및 이미지 수집 시, 조기 파싱으로 인한 글자 수 누락을 방지하기 위해 **본문 하단 스크롤 및 3~5초 완전 로딩 대기**를 실행한 후 `<div class="write_div">` 텍스트를 추출해야 합니다.
