# 문학 아카이브 통합 관리 에이전트 (.agent/AGENT.md)

## 📌 개요

이 에이전트는 디시인사이드 갤러리 문학 수집, 본문 파싱 고립성 유지, 정밀 태그 분류, 배치 통합 정돈, 데이터 빌드 및 Git 관리를 전담합니다.

---

## 🚨 [최우선 핵심 필수 수칙] 본문 파싱 고립성 &amp; 맥락 중심 태그 분류

### 1. 크롤링 시 본문 파싱 고립성 보장 수칙 (Scraped HTML Isolation)

- ⚠️ **HTML 구획 엄격 고립**: 게시글 수집 및 파싱 시, 디시인사이드 웹페이지 전체 HTML 중 **오직 작가가 작성한 순수 본문 컨테이너인 `<div class="write_div">` 내부 텍스트만 엄격하게 추출**해야 합니다.
- 🚫 **절대 제외 요소**:
  - 댓글 및 답글 전체 (`.comment_box`, `.reply_list` 등)
  - JavaScript 코드 및 스크립트 텍스트 (`<script>` 태그 내부 전체)
  - 사이드바, 갤러리 상하단 메뉴, 공지사항, 목록 테이블 (`.gall_list` 등)
  - 광고 및 관련 사이트 텍스트 (`.dc_ads` 등)
- 💡 **목적**: 텍스트 분석, 글자 수 계산, 태그 부여 시 사이트 잡다한 코드나 댓글 단어가 섞여 오작동하는 것을 100% 원천 차단합니다.

### 2. 단어 단위 오매칭 방지 및 전체 맥락/서사 중심 태그 판정 수칙

- 🚫 **단순 단어 매칭 절대 금지**:
  - 본문에 포함된 단어 1~2개(예: `가슴`, `가상`, `우주` 등)에 기계적으로 반응하여 태그를 부여하지 않습니다.
  - 예시: `"가슴이 아파져 온다"`(슬픔 표현)의 `가슴` 단어로 인해 `후방주의` 태그가 붙는 오작동, 또는 단순 VR 언급으로 `SF` 태그가 붙는 오작동을 엄격히 금지합니다.
- ⭕ **전체 서사/감정선 중심 판정 (Context-First)**:
  - **"이 글 전체가 독자에게 전달하고자 하는 핵심 주제와 서사적/정서적 결말이 무엇인가?"**를 기준으로 태그를 결정합니다.
  - 예시: Kaguya가 떠나며 Iroha가 눈물짓는 [8422]번 글은 억지 피폐나 성적 묘사, SF가 아닌 순수한 `**💧 슬픔**` 장르로 판정합니다.

---

### 3. 동적 렌더링 & 페이지 완전 로딩 대기 수칙 (Full Dynamic DOM Load Wait)

- ⚠️ **조기 수집/조기 분석 금지**:
  - 디시인사이드 특성상 레이지 로딩(Lazy Loading) 및 클라이언트 동적 스크립트 실행으로 인해 초기 HTML만 조기 수집하면 본문 텍스트 일부(몇백 자)나 이미지가 덜 로드될 수 있습니다.
  - 게시글 파싱 및 분석 전, **페이지 스크롤 다운(Scroll Down)을 실행하고 최소 3~5초 이상 완전 로딩 대기**를 진행하여 DOM 트리가 100% 완성된 후 텍스트와 글자 수를 측정하고 태그를 정독·판정합니다.

---

### 4. 🚨 [절대 금지] 사용자 커스텀 이미지 및 에셋 임의 덮어쓰기/롤백 금지 수칙 (Asset Preservation)

- 🛑 **사용자가 수정한 이미지/에셋 원본 복구 금지**:
  - `src/assets/Image/` 및 하위 폴더의 모든 로고, 배너, 썸네일, 헤더, 커버, 아이콘 등 사용자가 직접 제작/교체/지정한 이미지 에셋은 **절대 이전 기본값이나 크롤링 원본 이미지로 되돌리거나(롤백) 덮어써서는 안 됩니다**.
- 🔒 **데이터 파서 및 빌드 스크립트 실행 시 커스텀 이미지 경로 보존**:
  - `src/scripts/` 파서/빌더 실행 시, 사용자가 수동으로 매핑하거나 설정한 시리즈 커버 이미지(`image` 필드), 로고 경로, 커스텀 에셋 참조를 기본 크롤링 이미지 경로로 임의 초기화하지 않고 반드시 기존 커스텀 값을 보존해야 합니다.
- 🎨 **HTML / CSS / JS 내 커스텀 에셋 링크 보호**:
  - `<img>` 태그의 `src`, `data-light-src`, `data-dark-src`, CSS의 `background-image` 등 사용자가 지정한 에셋 연결을 사용자의 명시적인 교체 지시 없이 임의 수정하지 않습니다.

## 🎯 주요 워크플로우

1. **본문 및 사진 수집 (`crawling.md`)**:
  - `<div class="write_div">` 순수 본문 텍스트 및 고화질 원본 이미지 다운로드.
  - 단편/시리즈 통합 사진 저장 경로: `사진/1/` ~ `사진/29/`.
2. `**rules/tag.md` 참조 및 정밀 태그 분류**:
  - 분류 전 반드시 `.agent/tag_example/` 예시글 사전 읽기 후 벤치마킹.
  - `판타지`, `SF`, `미스테리` 태그는 사용 제외. `로카`, `IF 스토리` 태그는 AI 남발 방지를 위해 **AI 자동 부여 절대 금지 (사용자 직접 수동 지정 전용)**.
  - 분량 태그(`짧문`(1,000자 미만), `소설`(5,000자 이상)) 최전단 배치 + 핵심 장르 태그 최대 2~3개 제한.
3. **통합 마크다운 배치 정리 (`크롤링/1.md` ~ `29.md`) 및 마감 수칙**:
  - 기존 수집 문학은 최신 게시글 ID `281,889`번까지만 마감하여 `**크롤링/1.md` ~ `29.md`** 파일 범위로 통합 관리합니다.
  - 시리즈 문학도 별도 폴더로 나누지 않고 통합 수록하며, 메타데이터에 `**- **시리즈**: <시리즈명>**` 항목을 기록합니다.
  - 📅 `**29.md` 이후 수칙**: ID > 281,889 이후 신규 글은 `30.md` 등을 만들지 않고 **날짜별 수집(일별/주별 갱신)** 체계로 관리합니다.
4. **데이터 빌드 및 정적 사이트 연동 (`src/scripts/`)**:
  - 단편/시리즈/명예관/대회 데이터를 파싱하여 사이트용 `data.json`, `series_entries.json` 등 빌드.
  - 🚨 `**❌ 분류 안함` 태그 제외**: `❌ 분류 안함` 태그가 지정된 항목은 사용자의 "무조건 수동 검토" 전용이므로 **통계 집계 및 일반 문학 목록에서 제외**합니다.
5. **크롤링 현황 기록 (`CurrentStats.md`)**:
  - 수집 건수, 글자 수, 사진 장수 및 용량을 `CurrentStats.md`에 자동 갱신.
6. **GitHub 동기화 (사용자 명시적 요청 시에만 수행)**:
  - ⚠️ 매 소작업마다 자동 커밋/푸시를 실행하지 않습니다.
  - 사용자가 직접 **"git에 올려줘"**, **"푸시해줘"**, **"커밋해줘"**라고 지시할 때에만 커밋 및 `git push origin main`을 실행합니다.
